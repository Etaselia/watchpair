# Desktop and coordinator alpha.4 — 2026-10-30

Alpha.4 repairs restart into an older installed copy, makes the player move between room/fullscreen/window views, and gives Upcoming and Watched distinct, synchronized actions. Duplicate episode names retain stable identities; watched dates, download approval and torrent contribution controls have explicit behavior. Existing v2 room IDs, invites, credentials, profiles and media files are retained. The coordinator update is required for shared clears and history migration. v1 browser rooms remain separate from v2.

## Changes

- **Installation and recovery.** Settings separates running, installed and staged versions. Restart verifies the selected runtime before leaving the live session; a newer portable copy stages itself instead of opening an older installation. Installing an older version is rejected. Explicit recovery verifies the profile binding, prior runtime, backup checksum and SQLite database before quitting, then rechecks under installer/profile locks. Restoring the previous version discards an obsolete staged activation marker while retaining its runtime files.
- **Player.** One native player moves between the room, fullscreen and an optional player window. Overlay controls hide during playback and reappear on activity, pause or blocking states. Seek, chapters, audio, subtitles and volume preserve the shared timeline. Chapter choices reject metadata from a stopped renderer or a different episode, including an activation delivered before the next UI refresh.
- **Software graphics.** Detected CPU renderers use mpv's basic rendering path with bilinear scaling. The exact retained mpv 0.37/0.41 sources preserve tone mapping, target primaries/transfer/peak, HDR peak handling, ASS fonts and bitmap subtitles; chapters and audio selection remain outside this GPU option. Advanced scalers, interpolation, debanding and custom shaders are excluded from this software policy. Hardware-renderer behavior is unchanged. GL state is prepared before both render updates and draws.
- **Queue identity and selection.** Upcoming reorders by stable entry IDs with the original queue revision, preserving hidden rows. Marked episodes leave Upcoming as soon as the shared update arrives. Episode titles precede folder/source context so compact rows retain episode numbers; full tooltips preserve paths. Source fingerprints appear only when label and path also collide. Actions use selected stable IDs rather than filenames or a stale keyboard cursor.
- **Shared clears.** Each tab has its own actions and an in-app confirmation that explains every member is affected and files are retained. Clear Upcoming deselects enabled, unwatched entries. Clear Watched atomically removes watched queue entries and all shared history, including unloaded pages, while retaining Upcoming and media files. Removing the playing entry follows the existing advance behavior. Both operations use revision guards and idempotent replay; old history requests cannot repopulate a cleared list.
- **History dates and context.** Fractional epoch milliseconds previously became zero through Qt's integer-only conversion, producing roughly 20,755 days ago. New timestamps use integer Unix milliseconds. Migration updates legacy JSON and SQLite ordering together to preserve pagination. Missing path/source context is recovered only from exact entry/source IDs, including server-side folder search; filenames are never used to guess removed sources.
- **Download approval.** Upcoming offers approval for selected episodes on this device. A separate source action includes all upcoming episodes from selected sources, including hidden results, and confirms scope, size and source details. Local approval does not change another device's downloads or the room queue.
- **Transfers.** Torrent uploads default to off, with durable bounded/unlimited contribution choices and a native upload gate. Completed content displays Complete when contribution is off or its limit is reached. The ratio column uses selected size for existing copies with no download traffic, matching the contribution limit. Filter sizing follows desktop font metrics. Shared media tries authenticated encrypted direct TCP first; relay fallback is explicit and can be disabled. Authenticated alternative routes wait for the preferred outgoing attempt to fail or time out rather than promoting speculatively. This is not a full ICE/NAT traversal implementation.

## Upgrade bootstrap

Download and fully extract alpha.4 into a new directory, quit every older copy including the tray, and open the extracted app with the existing profile. In Settings → Application and updates confirm Running is `2.0.0-alpha.4`, install that running copy, and restart when ready. Confirm Running again. No profile deletion or replacement v2 room is needed. Once alpha.4 is running, the signed feed handles later releases normally.
